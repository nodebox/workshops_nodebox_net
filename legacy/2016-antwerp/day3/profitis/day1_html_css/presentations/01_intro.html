IP adres

Zoals we allemaal een thuisadres hebben, zo heeft ook elke website een adres: het IP-adres. EMRG zoek je door www.emrg.be in te typen, maar wij hebben ook gewoon een IP-adres.

Probeer 176.58.119.173 maar eens, het IP-adres van emrg.be, dan vind je onze onderzoekspagina's. Er bestaan tal van websites om IP adressen op te zoeken.

DNS

Domain Name System

Net zoals je niet alle telefoonnummers hooft te onthouden, zo hoef je ook niet alle IP-addressen te onthouden. Een speciale dienst, converteert een domeinnaam (emrg.be) naar een IP-adres. Die dienst heet DNS, of Domain Name System.

ISP

Internet Service Provider

De eerste stap bij het bezoeken is de lijn van jouw huis naar de Internet Service Provider, meestal Telenet of Proximus. Daar staat de DNS server die de vertaling doet van de naam naar het IP-adres, en die is ook de eerste stap naar het datacenter waar de juiste server staat.

De server

Websites staan opgeslagen op servers: computers met veel opslagruimte die makkelijk toegankelijk zijn via internet. Je kunt een server vergelijken met de kast in je kamer: er liggen allemaal dingen in opgeslagen. Het verschil is dat een server overal staat; je kan er - als je een internetverbinding hebt - altijd iets uitpakken.

Je ISP gaat op een snelle, slimme manier op zoek naar de server waarin de website is opgeslagen die jij wilt bezoeken.

en terug

Heeft de ISP de server gevonden, dan geeft die jouw verzoek door. Krijg je toegang tot de website, dan stuurt de server de bestanden die je wil zien in allemaal kleine pakketten terug. Die pakketten worden op jouw computer door de browser weer in elkaar gezet tot een leesbare website.

Het bijzondere aan het internet is dat de weg terug van de server naar jouw computer compleet anders kan zijn dan de weg van de computer naar de server. Dat zorgt ervoor dat alles wat hierboven staat in millisecondes kan gebeuren.

Bottom-up aanpak

  • Zelfredzaamheid
  • Samenwerking

We hebben er speciaal voor gekozen om je HTML en CSS te leren zodat je echt weet hoe pagina's gemaakt worden, en wat de code erachter is. Dit is belangrijk om verschillende redenen.

Je zou, in plaats van met HTML te werken, ook met een grafische editor werken. Die schrijft dan de HTML voor jou. Fantastisch!

Tot er iets mis gaat. De editor vormt een dun laagje boven de HTML en CSS: hij abstraheert als het ware de HTML en CSS tot een grafische omgeving.

Echter, door te doen alsof HTML en CSS niet bestaan loop je tegen problemen aan die je zelf niet kan oplossen. Een element staat niet op de juiste plaats? Als je nooit de HTML en CSS ziet weet je ook niet waar je moet beginnen zoeken.

Daarom is het belangrijk om te begrijpen hoe webpagina's gemaakt worden, alvorens je visuele tools gebruikt om pagina's aan te maken.

In de "echte " wereld zal je grote websites waarschijnlijk in team maken. Als je samenwerkt met een programmeur die de HTML en CSS voor jou doet is het nog steeds belangrijk om te begrijpen wat er mogelijk is. Dit laat de conversatie tussen jou en andere teamleden vlotter verlopen.

Alternatieven

Waarom niet Flash?

Toen we een aantal jaren deze cursus gaven, was "waarom niet Flash" een veelvoorkomende vraag.

Ondertussen is het wel duidelijk dat Flash nauwelijks nog gebruikt wordt voor nieuwe sites. En de reden is de iPhone. Apple heeft nooit Flash ondersteund op de iPhone, en dat heeft de ondergang van Flash teweeg gebracht.

Flash heeft ook een hele slechte reputatie qua toegankelijkheid voor mensen met een visuele handicap. Mensen die niet in staat zijn van visuele webpagina's te bekijken (zoals blinden) kunnen je flash-website niet bezoeken. Dit is misschien niet belangrijk als je een portfolio met grafisch werk maakt, maar wordt wel belangrijk als je websites ontwikkeld voor andere mensen.

Daarnaast zijn er de zoekmachines. Een site in Flash bevat bijna geen zinnige informatie voor zoekrobots, waardoor je website het erg povertjes zal doen in Google.

Door HTML/CSS/JavaScript te scheiden.

  1. Propere, semantische HTML heeft voordelen voor gebruikers die niet-visuele webbrowsers gebruiken, zoals blinden. Waarom die focus op blinden? Het web is een democratische tool. Maakt niet uit welke huidskleur je hebt, welke webbrowser je gebruikt of welke handicap je hebt. Daarnaast zijn er ook zoekrobotten die je website opzoeken, en die kunnen ook niet zien. Google leest je site en gebruikt vooral de structuur-informatie uit HTML om te bepalen wat belangrijk is.
  2. Je pagina wordt makkelijker overdraagbaar. Door HTML/CSS te scheiden kan je een nieuwe stylesheet implementeren en je hebt een mobiele versie van je pagina. We kunnen ook delen tussen verschillende projecten herbruiken.
  3. Je pagina's worden makkelijker te onderhouden. Een designer kan aanpassingen aan de CSS doen zonder de HTML te hoeven aan te passen of de JavaScript code te veranderen.
  4. Door HTML en CSS te scheiden moeten bezoekers van je website de CSS maar één keer downloaden, en gebruiken daarna de versie die ze in cache bewaren, wat de site sneller maakt.
